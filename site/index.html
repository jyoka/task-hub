task-hub

Your local coding agents turn each GitHub Project card you move to Ready into a reviewed PR.Ready に移した GitHub Project のカードを、手元のエージェントがレビュー済みの PR にする。

You move a card to Ready and merge the PR.人がするのは、カードを Ready に移すことと、PR をマージすることだけ。

task-hub and your agents do the rest: implement, test, review in a fresh context, open the PR, and sort out why a task stopped.その間の実装、テスト、新しい文脈のレビュー、PR、止まった理由の仕分けは、task-hub とエージェントが進める。

Each card leaves its report and review verdict on the Issue. Any agent CLI with a non-interactive mode works: Claude Code, Codex, Pi, Kiro, and others.どのカードも、Issue にレポートとレビューの判定が残る。非対話モードを持つエージェント CLI なら、どれでも動かせる(Claude Code、Codex、Pi、Kiro など)。

What it doesできること

The pictures are screens task-hub took of itself. Click one to open the docs for that feature (in Japanese).絵は task-hub が自分で撮った画面です。押すと、その機能の docs が開きます。

  • One PR per task1 タスク 1 PR

    Each card gets one branch, one worktree, and one PR.1 枚のカードに、1 つのブランチ、1 つの worktree、1 つの PR。

    Up to 5 run at the same time, on branches named task/<id>.最大 5 つを並べて動かし、ブランチは task/<番号>。

  • Pre-PR reviewPR の前のレビュー

    An agent in a fresh context checks each acceptance criterion.新しい文脈のエージェントが、受け入れ条件を 1 つずつ確かめる。

    It sends the work back 2 times at most by default. With review_mode = goldfish, two viewpoints that skip the report check it.差し戻しは既定で 2 回まで。review_mode = goldfish では、レポートを読まない 2 つの視点が見る。

  • task check 12 GONO-GO

    Goal checkGoal の確認

    task check <id> has agents that know only the Goal and the code say GO or NO-GO.task check <番号> で、Goal とコードだけを知るエージェントが GO / NO-GO を出す。

    A NO-GO comes with wording to add. With readiness = require, a card without a GO does not start.NO-GO には Goal に足す文言が付く。readiness = require なら、GO のないカードは始まらない。

  • crash→resume ×1 usage limit→wait, resume

    Stop recovery止まった後の再開

    A run that stops on a crash or a restart resumes once, from where it stopped.クラッシュや再起動で止まった実行を、止まった所から 1 回だけ再開する。

    A run that hits the usage limit waits for the reset time, then goes on from the same place.利用の上限で止まったら、戻る時刻を書いて待ち、戻ったら同じ所から続ける。

  • Blocked triageBlocked の仕分け

    An agent sorts out why a task stopped and comments on the Issue.止まった理由をエージェントが仕分けて、Issue にコメントする。

    Add the answer to the Goal, move the card to Ready, and the same PR continues.Goal に答えを足して Ready に戻すと、同じ PR で続く。

  • Merge queueマージキュー

    task merge approves a PR; the queue brings it up to date with its base, waits for its checks, and merges it.task merge で承認した PR を、base に追いつかせ、チェックを待ってマージする。

    An agent fixes conflicts. One PR per repository at a time.衝突はエージェントが直す。1 つのリポジトリで 1 度に 1 本。

  • Agent choiceエージェントの選択

    Any agent CLI with a non-interactive mode works.非対話モードを持つエージェント CLI なら、どれでも動かせる。

    task-hub does git, the PR, and the Issue comments in code, so every agent makes the same kind of PR.git、PR、Issue のコメントは task-hub がコードで行うので、どのエージェントでも同じ形の PR になる。

  • In reviewBlocked task stats

    Alerts and cost通知と費用

    In review, Blocked, long runs, and runs over budget show as OS notifications and on ntfy. No LLM is used.In review、Blocked、長い実行、予算超えを、OS の通知と ntfy で知らせる。LLM は使わない。

    Tokens and cost per launch come from the agent CLI's own records (task stats).起動ごとのトークンと費用を、エージェント CLI の記録から読む(task stats)。

Start in three steps3 手で始める

You need macOS (Windows: docs/windows.md), Python 3.10 or later, git, gh logged in, and at least one agent CLI logged in.要るのは macOS(Windows は docs/windows.md)、Python 3.10 以上、git、ログイン済みの gh、ログイン済みのエージェント CLI 1 つ以上です。

  1. 1 Install入れる 
    git clone https://github.com/jyoka/task-hub.git ~/.local/lib/task-hub
ln -sfn ~/.local/lib/task-hub/bin/task ~/.local/bin/task

    A clone of its own, apart from any clone you develop in. ~/.local/bin must be on your PATH. task update keeps it current.開発用とは別の、動かす用の clone。~/.local/bin を PATH に入れておく。更新は task update。

  2. 2 Let gh use Projectsgh に Project の権限 
    gh auth refresh -s project

    task-hub reads and moves the cards through gh.task-hub は gh でカードを読み、動かす。

  3. 3 Configure, then task設定して task 
    ; ~/.config/task-hub/config.ini
[board]
project = <owner>/<project number>
issues = <owner>/<repository that holds the Issues>

[runner]
agent = claude
reviewer = agent
    task list   # check the config設定を確かめる
task        # start Ready cardsReady のカードを始める

    reviewer = agent turns on the review before the PR. Prepare the Project's columns and fields with docs/setup.md.reviewer = agent で PR の前のレビューが動く。Project の列と欄の用意は docs/setup.md。
