# Windows の Kiro IDE で task-hub を使いはじめる(かんたんセットアップ)

Kiro IDE の画面とチャットだけで、task-hub を Windows に入れて最初のタスクを回すまでの手順です。PowerShell に
コマンドを打つ必要はありません。Kiro のチャットが、リポジトリの中のインストーラを代わりに実行します。
Mac の手順([kiro-quickstart.md](kiro-quickstart.md))と同じ流れです。

やることは 4 つです。

1. Kiro IDE でこのリポジトリを開く
2. チャットに「セットアップして」と言う
3. 止まったところで、開いた窓とブラウザでログインする
4. 「続けて」と言う

管理者のパスワードは一度も聞かれません(UAC の画面も出ません)。入れるものはすべて、自分のユーザーフォルダーの中
(`C:\Users\<自分>\.local` など)に置かれます。インストーラが何をしているかは [windows.md](windows.md) の 4 章に
あります(読まなくても使えます)。

## 前提

- **Windows 11**(Windows 10 でも進みますが、確かめているのは Windows 11 です)
- **Kiro IDE**。入れるのは情シスの配布に任せます
- **git**。Kiro IDE の「Clone Repository」自体が git を使います。無いときは手順 1 の「こうなったら」を見ます
- **GitHub のアカウント**
- 時間の目安: 30 分(ダウンロードの待ち時間を含みます。Kiro CLI は約 300 MB です)

git、GitHub CLI、Python、Kiro CLI は、無ければインストーラが入れます。

## 1. Kiro IDE でリポジトリを開く

1. Kiro IDE を開きます。最初の画面(Welcome)の「**Clone Repository**」を押します。
   最初の画面が出ていなければ、Ctrl+Shift+P(コマンドパレット)で「Git: Clone」を選びます。
2. 上に入力欄が出ます。「**Clone from GitHub**」を選びます。
   - GitHub へのログインを求められたら「Allow」を押します。ブラウザが開くので、GitHub にログインし、
     「Authorize」を押します。「Kiro を開きますか」と聞かれたら開きます。
3. リポジトリの一覧から `jyoka/task-hub` を選びます(出てこなければ、入力欄に
   `https://github.com/jyoka/task-hub` を貼り付けます)。
4. 保存先のフォルダーを聞かれます。ドキュメントなど、分かりやすい場所を選びます。
5. 「Would you like to open the cloned repository?」と出たら「**Open**」を押します。
6. 「Do you trust the authors of the files in this folder?」と出たら「**Yes, I trust the authors**」を押します。

**こうなったら:** 「git が見つかりません」(Git not found)と出る → git がありません。情シスに Git for Windows を
入れてもらうか、会社の決まりで自分で入れてよければ、https://git-scm.com/download/win のインストーラで入れます。
入れたら Kiro を開き直して、1 からやり直します。

## 2. チャットに「セットアップして」と言う

1. Kiro のチャット(右側の欄)を開き、**「セットアップして」** と書いて送ります。
2. Kiro が「コマンドを実行してよいか」を聞いてきたら、実行を許可するボタン(「Run」など)を押します。
   実行されるのは、このリポジトリの `windows\install.ps1`(インストーラ)だけです。
3. 数分待ちます。Kiro が、終わったことか、止まった理由と次にすることを 2〜3 行で伝えます。

インストーラは、1 から 11 までの段階を順に確かめ、足りないものだけを入れます。何度実行しても安全で、
止まったところから続きを進めます。

## 3. 止まったところでログインする

止まるのは、本人の操作が要るところだけです。Kiro が伝えた「次にすること」に従います。ログイン用の
**PowerShell の窓**(黒か青の画面)が 1 つ開きます。Kiro の後ろに隠れていたら、画面の下のタスクバーから選びます。

### GitHub のログイン

1. 開いた窓に案内が出ます。Enter を押すとブラウザが開きます。
2. 窓に出た 8 文字のコード(`ABCD-1234` の形)を、ブラウザの画面(`https://github.com/login/device`)に入れ、
   「Continue」を押します。
3. 「Authorize GitHub CLI」の画面で、緑の「**Authorize github**」を押します。組織の名前の横に「Authorize」が
   あれば、それも押します。
4. 「Congratulations, you're all set!」と出て、窓に「終わったら、この窓を閉じて…」と出たら、Enter を押して
   窓を閉じます。

コードは 15 分で切れます。切れたら、もう一度「続けて」と言えば、ログイン用の窓が開き直されます。

### kiro-cli のログイン

タスクを実行する kiro-cli にも、別にログインします。

1. ログイン用の窓が 1 つ開きます。
2. ログインの方法を、上下の矢印キーで選び、Enter を押します。会社のアカウントなら、情シスに聞いた方法
   (IAM Identity Center なら start URL と region)を選んで入れます。
3. ブラウザが開くので、ログインして承認します(「Confirm and continue」「Allow access」など)。
4. 窓に「終わったら、この窓を閉じて…」と出たら、Enter を押して窓を閉じます。

## 4. 「続けて」と言う

ログインが終わったら、チャットに **「続けて」** と書きます(新しいチャットで言うときは「**セットアップを続けて**」)。
インストーラが残りの段階を進め、最後に **診断** の一覧を出します。

```
○ 7. ボード: https://github.com/users/<あなた>/projects/<番号>、<あなた>/tasks
○ 9. Kiro との連携: スキル、steering、フック、ワークフロー、Workflows は有効
○ 11. Slackトリアージ: Slack のスレッドをコピーして Ctrl+Alt+S で使えます
```

すべて ○ なら、セットアップは終わりです。途中で、自分用のタスクボード(GitHub の private のリポジトリ
`<あなた>/tasks` と、Project「task-hub」)も作られています。

### 画面での操作が残ったとき

- **「…/workflows を開き、「Item closed」を有効にしてください」**: Kiro が伝えたアドレスをブラウザで開きます。
  左の一覧で「Item closed」を選び、「Edit」→「Save and turn on workflow」を押します(画面によっては、右上の
  スイッチを On にします)。
- **「Enable Workflows」を実行してください**: Kiro で Ctrl+Shift+P を押し、「Enable Workflows」と入れて選びます。

終わったら、もう一度「続けて」と言います。

## 5. Kiro を再起動して、最初のタスク

1. メニューの「File」→「Exit」(またはウィンドウを閉じる)で Kiro を終了し、開き直します。
2. **新しいチャット** を開き、`/` を打ちます。候補に `task` と `chief` が出れば、入っています。
3. 何か頼みたい作業について話してから `/task` と送ると、ボードの Backlog にカードができます。
4. ブラウザでボード(Project)を開き、カードを Ready に移します。タスクが始まり、終わると In review になって、
   画面の右下に Windows の通知が出ます。

カードを Ready に移したときに自動で始めるには、次の「常駐」を入れます。

### 常駐(任意)

Kiro を閉じていても、Ready のカードを自動で始めるしくみです。チャットで **「常駐も入れて」** と言います。
Kiro が「始めてよいか」を聞いてくるので、よければ「はい」と答えます。サインインのたびに自動で始まります。

### Slack からタスクにする(Ctrl+Alt+S)

Slack のスレッドの文章を選んでコピー(Ctrl+C)し、**Ctrl+Alt+S** を押すと、Kiro がスレッドを読んで、登録する
タスクを提案します。登録するかは毎回、画面で決めます。初めて押したときだけ、あなたの名前と登録先の
リポジトリを聞きます。ほかのアプリが Ctrl+Alt+S を使っているときは、セットアップがそう伝えるので、
`slack-triage key t` のように別のキーにします。使い方は [slack-triage.md](slack-triage.md) にあります。

## 新しい版にするとき

入るのは、task-hub の担当者が確かめて出した、一番新しい版(`kiro-v1`、`kiro-v2` … のタグ。まだ出ていないうちは、
最新のもの)です。新しい版が出たら、チャットでもう一度 **「セットアップして」** と言うだけで切り替わります。

## うまくいかないとき

まず、チャットで **「診断して」** と言います。何も変えずに、全段階を確かめて、○ と × の一覧を出します。
× の行の下の「→」が、次にすることです。

| 出てきたこと | すること |
|---|---|
| 「この PC の PowerShell は機能が制限されています」と、情シスへの依頼文 | 依頼文をそのまま情シスに送り、使えるようになったら「続けて」 |
| 「GitHub に届きません」「ダウンロードできませんでした」 | VPN やプロキシを確かめて「続けて」。会社のプロキシがあるなら、情シスにプロキシのアドレスを聞き、「プロキシは http://ホスト:ポート で続けて」と言う |
| 「チェックサムが合いません」 | ダウンロードが壊れたか、すり替わっています。時間をおいて「続けて」。続くときは task-hub の担当者に知らせる |
| 「入れた git(gh、kiro-cli)が動きません」 | 会社のセキュリティが、ユーザーフォルダーのプログラムを止めています。情シスに相談する |
| 「Kiro CLI の MSI を展開できませんでした」 | 空き容量(約 1 GB)を確かめて「続けて」。続くときは、情シスに Kiro CLI を入れてもらう |
| 「開いた窓で、案内に沿ってブラウザで承認してください」 | 3 章のとおりログインし、「続けて」 |
| 「起動キー Ctrl+Alt+S は、ほかのアプリが使っています」 | PowerShell を開いて `slack-triage key t` と打ち(Ctrl+Alt+T になります)、チャットで「続けて」 |
| 「インストーラが入れた内容と確認できないので書き換えていません」 | 独自に変更したファイルがあります。移すか残すかを task-hub の担当者に相談する |
| 「環境変数 GH_TOKEN があるので…」 | task-hub の担当者に相談する |
| 「… がすでにあります(このインストーラが作ったものではありません)」 | 前に手で入れたものがあります。task-hub の担当者に相談する |

ログインについて、知っておくと迷わないことが 2 つあります。

- **kiro-cli のログインは、切れることがあります。** 切れると、kiro で動かすタスクは、始める前の確認で止まります。
  「診断して」と言うと、「5. kiro-cli のログイン」が × になっているので分かります。チャットで「続けて」と言えば、
  ログイン用の窓が開きます。
- **Kiro IDE のログインと kiro-cli のログインは、別です。** タスクを動かすのは kiro-cli なので、そちらのログインが要ります。

### やめるとき(アンインストール)

チャットで **「アンインストールして」** と言います。消すものの一覧が出るので、よければ「はい」と答えます。
消すのは、インストーラが入れたものだけです。作業中のタスクがあるときは、常駐だけを止めて、終わってから
もう一度と案内します。GitHub のボード(`<あなた>/tasks` と Project)は消しません。要らなければ、一覧の最後に
出るアドレスを開き、GitHub の画面の一番下の「Delete」で消します。
