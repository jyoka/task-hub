# Kiro IDE で task-hub を使いはじめる(かんたんセットアップ)

Kiro IDE の画面とチャットだけで、task-hub を入れて最初のタスクを回すまでの手順です。ターミナルにコマンドを打つ
必要はありません。Kiro のチャットが、リポジトリの中のインストーラを代わりに実行します。

やることは 4 つです。

1. Kiro IDE でこのリポジトリを開く
2. チャットに「セットアップして」と言う
3. 止まったところで、ブラウザでログインする
4. 「続けて」と言う

管理者のパスワードは一度も聞かれません。入れるものはすべて、自分のホームフォルダの中に置かれます。
インストーラが何をしているかは [kiro-ide.md](kiro-ide.md) にあります(読まなくても使えます)。

## 配る人へ: 配る前に確かめること

1. **同僚の Mac に git(Xcode の Command Line Tools)が入っているか。** Kiro IDE の「Clone Repository」とインストーラは、
   どちらも git を使います。git が無いと手順 1 で止まり、インストーラでは入れられません(管理者権限が要ることがあるため)。
   入っていなければ、情シスに配ってもらいます。
2. **同僚を dip-ka-jo/task-hub に招待しておく。** GitHub の collaborator として招待し、同僚が招待を受け入れると
   「Clone Repository」で開けるようになります。個人のリポジトリなので、招待した人には書き込みの権限も付きます。

## 前提

- **Kiro IDE**(1.2 以上)。版はメニューの「Kiro」→「About Kiro」で見られます。入れるのは情シスの配布に任せます。
- **git**(Xcode の Command Line Tools)。Kiro IDE の「Clone Repository」自体が git を使うので、git が無いと
  手順 1 で止まります。インストーラでは入れられません(管理者権限が要ることがあるため)。
- **GitHub のアカウント** で、dip-ka-jo/task-hub を読めること。
- 時間の目安: 30 分(ダウンロードの待ち時間を含みます)。

## 1. Kiro IDE でリポジトリを開く

1. Kiro IDE を開きます。最初の画面(Welcome)の「**Clone Repository**」を押します。
   最初の画面が出ていなければ、⌘⇧P(コマンドパレット)で「Git: Clone」を選びます。
2. 上に入力欄が出ます。「**Clone from GitHub**」を選びます。
   - GitHub へのログインを求められたら「Allow」を押します。ブラウザが開くので、GitHub にログインし、
     「Authorize」を押します。「Kiro を開きますか」と聞かれたら開きます。
3. リポジトリの一覧から `dip-ka-jo/task-hub` を選びます(出てこなければ、入力欄に
   `https://github.com/dip-ka-jo/task-hub` を貼り付けます)。
4. 保存先のフォルダを聞かれます。書類フォルダなど、分かりやすい場所を選びます。
5. 「Would you like to open the cloned repository?」と出たら「**Open**」を押します。
6. 「Do you trust the authors of the files in this folder?」と出たら「**Yes, I trust the authors**」を押します。

**こうなったら:** 「git が見つかりません」と出る、または「コマンドライン・デベロッパツールが必要です」という
ダイアログが出る → git がありません。情シスに Command Line Tools を入れてもらってください(自分で「インストール」を
押してよいかは、会社の決まりに従います)。

## 2. チャットに「セットアップして」と言う

1. Kiro のチャット(右側の欄)を開き、**「セットアップして」** と書いて送ります。
2. Kiro が「コマンドを実行してよいか」を聞いてきたら、実行を許可するボタン(「Run」など)を押します。
   実行されるのは、このリポジトリの `kiro/install.sh`(インストーラ)だけです。
3. 数分待ちます。Kiro が、終わったことか、止まった理由と次にすることを 2〜3 行で伝えます。

インストーラは、1 から 11 までの段階を順に確かめ、足りないものだけを入れます。何度実行しても安全で、
止まったところから続きを進めます。

## 3. 止まったところでログインする

止まるのは、本人の操作が要るところだけです。Kiro が伝えた「次にすること」に従います。

### GitHub のログイン

1. ブラウザで `https://github.com/login/device` が開きます(開かなければ、Kiro が伝えたアドレスを開きます)。
2. Kiro が伝えた 8 文字のコード(`ABCD-1234` の形)を入れ、「Continue」を押します。
3. 「Authorize GitHub CLI」の画面で、緑の「**Authorize github**」を押します。組織の名前の横に「Authorize」が
   あれば、それも押します。
4. 「Congratulations, you're all set!」と出たら終わりです。

コードは 15 分で切れます。切れたら、もう一度「続けて」と言えば、ログイン用のウィンドウが開き直されます。

### kiro-cli のログイン

タスクを実行する kiro-cli にも、別にログインします。

1. 「ターミナル」のウィンドウが 1 つ開きます。
2. ログインの方法を、上下の矢印キーで選び、Enter を押します。会社のアカウントなら、情シスに聞いた方法
   (IAM Identity Center なら start URL と region)を選んで入れます。
3. ブラウザが開くので、ログインして承認します(「Confirm and continue」「Allow access」など)。
4. ターミナルに「終わったら、このウィンドウを閉じて…」と出たら、ウィンドウを閉じます。

## 4. 「続けて」と言う

ログインが終わったら、チャットに **「続けて」** と書きます(新しいチャットで言うときは「**セットアップを続けて**」)。
インストーラが残りの段階を進め、最後に **診断** の一覧を出します。

```
○ 7. ボード: https://github.com/users/<あなた>/projects/<番号>、<あなた>/tasks
○ 9. Kiro との連携: スキル、steering、フック、ワークフロー、Workflows は有効
```

すべて ○ なら、セットアップは終わりです。途中で、自分用のタスクボード(GitHub の private のリポジトリ
`<あなた>/tasks` と、Project「task-hub」)も作られています。

### 画面での操作が残ったとき

- **「…/workflows を開き、「Item closed」を有効にしてください」**: Kiro が伝えたアドレスをブラウザで開きます。
  左の一覧で「Item closed」を選び、「Edit」→「Save and turn on workflow」を押します(画面によっては、右上の
  スイッチを On にします)。
- **「Enable Workflows」を実行してください**: Kiro で ⌘⇧P を押し、「Enable Workflows」と入れて選びます。

終わったら、もう一度「続けて」と言います。

## 5. Kiro を再起動して、最初のタスク

1. メニューの「Kiro」→「Quit Kiro」(⌘Q)で Kiro を終了し、開き直します。
2. **新しいチャット** を開き、`/` を打ちます。候補に `task` と `chief` が出れば、入っています。
3. 何か頼みたい作業について話してから `/task` と送ると、ボードの Backlog にカードができます。
4. ブラウザでボード(Project)を開き、カードを Ready に移します。タスクが始まり、終わると In review になって
   macOS の通知が届きます。

カードを Ready に移したときに自動で始めるには、Kiro を開いておくか、次の「常駐」を入れます。

### 常駐(任意)

Kiro を閉じていても、Ready のカードを自動で始めるしくみです。チャットで **「常駐も入れて」** と言います。
Kiro が「始めてよいか」を聞いてくるので、よければ「はい」と答えます。

## 新しい版にするとき

入るのは、task-hub の担当者が確かめて出した、一番新しい版(`kiro-v1`、`kiro-v2` … のタグ)です。新しい版が出たら、
チャットでもう一度 **「セットアップして」** と言うだけで切り替わります。

## うまくいかないとき

まず、チャットで **「診断して」** と言います。何も変えずに、全段階を確かめて、○ と × の一覧を出します。
× の行の下の「→」が、次にすることです。

| 出てきたこと | すること |
|---|---|
| 「git がありません」と、情シスへの依頼文 | 依頼文をそのまま情シスに送り、入ったら「続けて」 |
| 「GitHub に届きません」 | VPN やプロキシを確かめて「続けて」。「自動プロキシ設定(PAC)」と出たら、情シスにプロキシのホストとポートを聞き、「プロキシは http://ホスト:ポート で続けて」と言う |
| 「チェックサムが合いません」「署名を確かめられませんでした」 | ダウンロードが壊れたか、すり替わっています。時間をおいて「続けて」。続くときは task-hub の担当者に知らせる |
| 「Kiro CLI の DMG を開けませんでした」 | 情シスに Kiro CLI を入れてもらい、「続けて」 |
| 「ブラウザでの承認を待っています」 | 3 章のとおりコードを入れて承認し、「続けて」 |
| 「環境変数 GH_TOKEN があるので…」 | task-hub の担当者に相談する |
| 「… がありますが、このインストーラが作ったものではありません」 | 前に手で入れたものがあります。task-hub の担当者に相談する |
| Kiro の設定に Workflows が無い | そのアカウントではまだ使えません。フックと通知だけで使えます |

ログインについて、知っておくと迷わないことが 2 つあります。

- **kiro-cli のログインは、切れることがあります。** 会社のアカウント(IAM Identity Center)のログインが、一晩で
  切れていたことがあります(2026-10-02 に確認)。切れると、kiro で動かすタスクは、始める前の確認で止まります。
  「診断して」と言うと、「5. kiro-cli のログイン」が × になっているので分かります。`kiro-cli login` で
  ログインし直します(チャットで「続けて」と言えば、`kiro-cli login` を動かすターミナルのウィンドウが開きます。
  やり方は 3 章の「kiro-cli のログイン」と同じです)。
- **Kiro IDE のログインと kiro-cli のログインは、別です。** Kiro IDE にログインできていても、kiro-cli は
  ログインしていないことがあります(逆もあります)。タスクを動かすのは kiro-cli なので、そちらのログインが要ります。

### やめるとき(アンインストール)

チャットで **「アンインストールして」** と言います。消すものの一覧が出るので、よければ「はい」と答えます。
消すのは、インストーラが入れたものだけです。GitHub のボード(`<あなた>/tasks` と Project)は消しません。
要らなければ、一覧の最後に出るアドレスを開き、GitHub の画面の一番下の「Delete」で消します。
