## 判断と変更

| 対象 | 確認した問題 | 変更 |
|---|---|---|
| 再実行の作業先 | Blocked のカードの Target repo を変えると、指示の repo と worktree の origin が食い違う | 保存した repo と違えば、clone や実行を始める前に拒否 |
| 片付け | Target repo の現在値で片付けると、元のローカルブランチが残る | 保存した実行の repo・worktree・タブを使う |
| 実行記録 | stage 更新で JSON を空にしてから書く間に `task list` が読むとクラッシュする | プロセスごとの一時ファイルを書き終えてから原子的に置き換える |
| ボード・Issue・設定 | 表示と処理が同じ情報を繰り返し読む | sync の結果を表示に使い、開始時の Issue を共有。設定はコマンド単位で保持 |
| GitHub ログイン | バックグラウンドと Terminal の二つの経路、PID・ログ・コード待機を持つ | Kiro と同じ Terminal の一つの経路に統一 |
| Kiro のファイルの所有権 | 利用者の書き換えた hook を上書きし、差し替えたリンクをアンインストールで消す | 作成時の内容・リンク先を照合し、利用者の変更を保護 |

watch は確認ごとに runner などの設定を読み直す。[board] の変更は従来どおり監視の再起動が必要。
一時ファイルを使う修正は JSON の破損を防ぐもので、複数マシンの実行を調停する仕組みではない。

## 再レビューで追加した確認

- 修正前の CLI テストは、repo 変更後の再実行が In review になること、元のブランチが片付かないこと、
  書き込み途中の JSON を読んで `JSONDecodeError` になることを確認して失敗した。修正後は同じテストが成功。
- 変更された hook、既存の独自 hook、差し替えられた skill / kiro-cli のリンクは、CLI テストで保護を確認する。
- 旧版の所有記録に内容の識別情報がなくても、更新前の clone と一致するコピーは確認してから更新できる。
- 途中でインストールが止まっても、それまでに作成した資源を直ちに記録する。
- Terminal へ渡すログインコマンドは、設定したプロキシ・設定先・証明書の環境変数だけを引き継ぐ。
  インストーラと同じ環境で実行するだけでは欠落を検出できないので、引き継がない環境での CLI テストを追加した。
  コマンドは権限 0700 の一時ファイルから置き換え、認証を始める前に自分自身を削除する。
- 最終確認の本体 142 テストでは、操作の検証は成功したがテスト後処理で `Directory not empty` が一度出た。
  作られた直後の通知プロセスが最初の ps の一覧に見えない場合、片付けが早く終わることを別のテストで再現した。
  片付けは短い静止期間を確認するように修正した。これはテストの後処理だけの変更で、実行中のユーザープロセスには触れない。
- 出荷前の新しい担当によるレビューで、初回の環境ファイル不足で worktree だけが残る経路を確認した。
  作成直後に所属先を記録する。旧版の記録のない worktree も、Git の所属先を照合してから記録・再利用する。
  作業先の変更、開始失敗後の片付け、大文字小文字だけの変更、旧版からの再実行を CLI の再現テストに追加した。
  元の Base branch の記録は、変更可否の判定前には書き換えない。
